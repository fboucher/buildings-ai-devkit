# ADR-0003: Internal docs repo is the source of truth

- Status: Accepted (revised 2026-11-06: exporter moved to the internal docs repo)
- Date: 2026-11-05

## Context

API documentation is maintained as MkDocs markdown in a private internal repo that is not
reachable from outside the corporate network.

## Decision

- The internal docs repo stays the source of truth.
- `content/api/` in this repo is a **generated artifact**, fully overwritten on each export.
  It is never edited by hand.
- Content problems found during export are fixed upstream in the internal docs repo, or by
  improving the exporter rules there.
- `content/brick/`, `content/guides/` and `content/examples/` are authored in this repo and
  never touched by the exporter.
- **Split of responsibilities:**

  | Internal docs repo | This repo (public) |
  |---|---|
  | The exporter (source docs → `content/api/`) | `content/` (exported and authored pages) |
  | Export config (nav filter, cleared images) | Content validator (`devkit validate`) |
  | Block list of sensitive terms | Generators: `llms.txt` now; skill (P2), docs MCP server (P3) |
  | Later: CI that runs the export and opens PRs here | CI, GitHub Pages publishing |

- The exporter runs inside the network: locally against a clone (P1-P4), then in internal
  CI (P5). It writes into a local clone of this repo, runs this repo's `devkit validate`
  on the result before writing, then `devkit llms`, and can open the PR here.
- **No AI is involved in producing the content.** The export is a plain, deterministic
  script: the same source always produces the same output, so every diff can be reviewed
  and traced to a source change or a rule change.

## Rationale for the split

- The exporter can only run where the source is reachable, next to its block list.
- Generators must stay here: authored pages (guides, Brick) never pass through the source
  repo, and every PR here must be validated and regenerated by this repo's CI.

## Consequences

- The contract between the two repos is: pages that pass `devkit validate`, plus
  `content/api/_source.json` (source commit, exporter version, page order).
- Changes to the exporter need review in the internal docs repo.
